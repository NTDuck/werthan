## Audit-wave-1 scope corrections

- **D7 (package-manager dependency surface) is out of scope** (RefuteCover F1): a harness adapter executes commands in an existing environment; it does not translate manifests or synthesize dependency mappings (`requests`→`reqwest`). D7 is reclassified as a **dataset/coverage boundary** like G8: PASIPHAE handles in-repo dependency graphs (D6, D8); third-party manifest translation is explicitly declared a non-goal, and any project requiring it is classified partial-credit `dependency_untranslated`. Foreclosure claims removed from R6.
- **F4 double-count fixed** (RefuteCover F4): R1 and R6 record and execute receipts; neither prevents the toml vacuous pass. F4 is foreclosed by R2 + R8 only; the Forecloses columns were corrected.
- **Tier-C validation corpus gap (G8a, RefuteCover F6)**: PASIPHAE retains Tier C machinery (R12) but the corpus cannot exercise it. New requirement **R13**: any code path implementing SCC condensation, composite-vertex re-entry, or macro-regression must ship synthetic validation contracts (VAL-SPLIT / VAL-ASSEMBLY families per RefuteFeas F6) exercised by `cargo test --workspace` before the machinery may claim certification. Differentiating claims that cannot be validated on this corpus must be labeled `unexercised` in receipts rather than implied by architecture.
- **R12 residual**: G8c stands — non-monotonic recovery and warm-start resume remain `unexercised` on the current corpus; R13's synthetic contracts are the only validation route.

## Deliberately **not** requirements

- Frontier-model capability (outside regime) — R11 is capped to the fixed regime.
- Dataset construction (G8 acknowledgment; not fixable by methodology) — but R13 forces synthetic validation for anything the corpus cannot exercise.
- Benchmark redesign (non-goal) — accept is hardened from the inside (R2), not rebuilt.
- Third-party manifest/dependency translation (D7, RefuteCover F1) — out-of-scope boundary; classified `dependency_untranslated`.
