## 6. Methodological Derivation & Gate 5 Invariant Analysis

### 6.1. Mathematical Formulation of the Gate 5 Invariant
Under the THESEUS verification methodology (Criteria 2, [ADR-0015](../../decisions/0015-methodology-validation-contracts.md), and VAL-GATE5-02), the benchmark evaluation harness must satisfy the **Test Suite Immutability Invariant**:

$$\text{TargetTestSuite} \cap \text{RepairCandidatePool} = \emptyset$$

Let $\mathcal{W}$ be the workspace state, partitioned into the production code $\mathcal{P} \subset \mathcal{W}$ and the ground-truth characterization test suite $\mathcal{T}_{\text{orig}} \subset \mathcal{W}$.

An automated repair or modernization agent $\mathcal{A}$ generates mutations $\Delta \mathcal{W}$. Under Gate 5, the action space of $\mathcal{A}$ is formally restricted:

$$\text{dom}(\Delta \mathcal{W}) \subseteq \mathcal{P}, \quad \text{dom}(\Delta \mathcal{W}) \cap \mathcal{T}_{\text{orig}} = \emptyset$$

The evaluation metric $V(\mathcal{W})$ is defined as:

$$V(\mathcal{W}) = \begin{cases} 
\text{Pass} & \text{if } \text{Compile}(\mathcal{P}) = 0 \land \text{Exec}(\mathcal{T}_{\text{orig}}, \mathcal{P}) = 0 \land \text{Stubs}(\mathcal{P}) = 0 \\ 
\text{Fail} & \text{otherwise} 
\end{cases}$$
