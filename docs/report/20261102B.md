### 9.3. Forensic Breakdown: Why Did 92 Tests Pass?
The 10.36% pass rate represents genuine black-box execution of the compiled binary (`target/release/jp`), which was linked against an earlier intermediate candidate of `src/lib.rs`. In that candidate, `search()` was implemented as:

```rust
pub fn search(expression: &str, json_str: &str) -> Result<String, String> {
    if expression.is_empty() {
        return Err("Empty expression".to_string());
    }

    let _value: Value = serde_json::from_str(json_str)
        .map_err(|e| format!("Invalid JSON: {}", e))?;

    // Identity expression
    if expression == "@" {
        return Ok(json_str.trim().to_string());
    }

    Ok("null".to_string())
}
```

This diagnostic stub achieved 92 test passes due to two behavioral characteristics of the official JMESPath compliance suite:
1. **Identity Expression Compliance**: Tests querying `@` (the current node) against valid JSON documents immediately succeeded because the stub correctly validated JSON syntax and echoed the trimmed input.
2. **Null-Valued Invariants**: In JMESPath semantics, evaluating non-existent keys against JSON objects or missing indices against arrays evaluates to `null`. A substantial subset of compliance tests in `basic.json` and `indices.json` verify that absent keys or null fields yield `"null"`. The fallback return `Ok("null".to_string())` happened to satisfy these specific test cases.
3. **Syntax and Complex Expression Rejections (796 Failures)**: Every test requiring non-trivial AST evaluation—including filter projections (`foo[?bar == 'baz']`), wildcards (`foo.*.baz`), multi-select lists/hashes (`foo.[a, b]`), function calls (`length(@)`, `keys(@)`), and negative syntax error assertions—failed, as the binary neither computed expressions nor exited with non-zero error codes on invalid JMESPath syntax.

### 11.2. Root-Cause Autopsy: Rust Type-System Impedance
Detailed forensic analysis of `benchmarks/logs/jmespath_run.log` and the modernized workspace exposes the three root causes behind the compilation stoppage:

#### 1. Recursive Algebraic Data Types without Indirection (`E0072`)
- **Go Semantics**: In Go, abstract syntax tree nodes are expressed via structs containing slices or pointer fields:
  ```go
  type ASTNode struct {
      NodeType ASTNodeType
      Value    interface{}
      Children []ASTNode
  }
  ```
  In Go, a slice (`[]ASTNode`) is a 24-byte pointer-backed descriptor pointing to heap memory. It has a known, fixed size at compile time, regardless of AST depth.
- **Rust Translation Pathology**: The local SLM translated Go's AST representation into an idiomatic Rust algebraic data type (`enum AstNode`), but emitted recursive child nodes directly inline as enum variant payloads:
  ```rust
  pub enum AstNode {
      Identity,
      Field(String),
      Projection(AstNode, AstNode),                  // Infinite size!
      FilterProjection(AstNode, AstNode, AstNode),   // Infinite size!
      Comparator(ComparatorOp, AstNode, AstNode),   // Infinite size!
      AndExpression(AstNode, AstNode),              // Infinite size!
      OrExpression(AstNode, AstNode),               // Infinite size!
  }
  ```
- **Compiler Rejection**: Because `AstNode` directly contains instances of `AstNode` without indirection (`Box<AstNode>`), calculating `std::mem::size_of::<AstNode>()` produces an infinite geometric expansion. `rustc` immediately rejected the unit with `error[E0072]: recursive type AstNode has infinite size`.
- **MCTS Repair Stagnation**: During rollouts 1 through 64 on `interpreter.go`, the ARIADNE repair agent repeatedly attempted to patch method implementations inside `impl AstNode`, but repeatedly failed to insert `Box<AstNode>` into the enum definition itself, leading to diagnostic saturation.

#### 2. Crate Root Namespace Saturation (Wildcard Re-Export Collisions)
- The synthesis agent populated `src/lib.rs` with blanket `pub use <module>::*;` glob statements for all 15 modules.
- In Go, package `jmespath` aggregates multiple files into a single flat package namespace where unexported symbols are package-private.
- When lowering to Rust modules, multiple files declared types with identical names (`AstNodeType` in `astnodetype_string.rs` and `parser.rs`; `Value` in `interpreter.rs` and `serde_json`; `objs_equal` in `util.rs` and `util_test.rs`).
- The indiscriminate glob re-exports caused 23 `ambiguous_glob_reexports` warnings and obscured cross-module type resolution.

#### 3. Rollout Budget Exhaustion on Isolated Vertices
- When a module lacked an active downstream contract counterparty (such as `functions.go` which implemented 26 standalone JMESPath builtins like `abs`, `ceil`, `sort_by`), the module exhausted its 64-rollout MCTS budget without reaching full type unification.
- Rather than entering an infinite loop, the engine logged `BudgetExhausted { proof_trace: "Rollout budget exhausted on parentless module functions.go with no contract counterparty" }` and cleanly parked the module at futile dispatch 2, adhering to formal cycle-breaking invariants.

## 12. Architectural Guidance & Future Remediation for Scaling Beyond 10k LOC

To conquer the "Scaling Collapse" documented in arXiv:2602.22518 and push pass rates from 10% to >80% on multi-module repositories, the following four architectural enhancements are scheduled for implementation:

```
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │                  FOUR-POINT SCALING REMEDIATION ARCHITECTURE                │
 └─────────────────────────────────────────────────────────────────────────────┘
                                        │
        ┌───────────────────────┬───────┴───────────────┬───────────────────────┐
        ▼                       ▼                       ▼                       ▼
  [Codegen AST Linter]    [Explicit Re-Exports]   [Solver Portfolio Π]    [Black-Box Compaction]
  Auto-box recursive      Synthesize explicit     Escalate to MCTS only   Compact external pytest
  enum variants (E0072)   item exports in lib.rs  under high uncertainty  diagnostics into repair
```

### 12.1. Structural Codegen Linters: Recursive Enum Boxing (`E0072` Auto-Indirection)
- **Mechanism**: Implement a pre-compiler static analysis pass in `holon_engine` targeting Rust ASTs.
- **Invariant**: Scan all `enum` definitions. For any variant payload $V_k$ referencing the parent enum $E$ directly ($E \in \text{Payload}(V_k)$), automatically rewrite the payload to `Box<E>`:
  ```rust
  // Before Auto-Indirection
  Projection(AstNode, AstNode)
  
  // After Auto-Indirection Pass
  Projection(Box<AstNode>, Box<AstNode>)
  ```
- **Impact**: Completely eliminates `error[E0072]` at zero LLM token cost, immediately unblocking downstream AST interpretation and compilation.

### 12.2. Explicit Signature-Driven Crate Root Synthesis (Banning Wildcard Globs)
- **Mechanism**: Forbid blanket `pub use <module>::*;` in `lib.rs` synthesis.
- **Invariant**: Crate root exports must be explicitly synthesized from the public API interface contracts mined during macro-state $S_4$ (`BriefContracts`). Test modules (`*_test.rs`) must be isolated behind `#[cfg(test)]` attributes and never publicly re-exported into the library root.
- **Impact**: Prevents namespace collisions, silences all 23 glob re-export warnings, and ensures clean symbol resolution across module boundaries.

### 12.3. Full Multi-Strategy Solver Portfolio ($\Pi$) Implementation
- **Mechanism**: Accelerate the deployment of the full solver portfolio codified in METHODOLOGY2 ([ADR-0019](../../decisions/0019-methodology2-egagm.md)):
  $$\Pi = \{\pi_{\text{direct}}, \pi_{\text{repair}}, \pi_{\text{best-first}}, \pi_{\text{MCTS}}, \pi_{\text{joint}}\}$$
- **Invariant**: Routine utility modules (`util.go`, `toktype_string.go`) must be solved via low-cost direct pass ($\pi_{\text{direct}}$) or shallow race ($\pi_{\text{best-first}}$), reserving deep 64-rollout MCTS ($\pi_{\text{MCTS}}$) exclusively for high-uncertainty grammar parsers and AST interpreters.
- **Impact**: Reduces total token consumption by an estimated $\sim 65\%$, compressing the 2-hour wall-clock envelope down to under 45 minutes while concentrating search budgets where structural complexity demands it.

### 12.4. Black-Box Diagnostic Error Compaction Feedback
- **Mechanism**: In accordance with [ADR-0018](../../decisions/0018-frequent-intentional-compaction.md) and [ADR-0020](../../decisions/0020-repomod-benchmark-integration.md), integrate pytest test-failure summaries directly into the Tier-2 repair loop.
- **Invariant**: When external black-box tests fail, capture CLI `stdout`, `stderr`, and exit statuses, summarize failure clusters (e.g. "Expression `foo.*.baz` expected `['val', 'val']` but received `null`"), and feed compacted diagnostic summaries into repair prompts without leaking test implementation code.
- **Impact**: Enables the agent to iteratively refine AST evaluation logic based on black-box behavior, bridging the gap between basic syntax passes and full JMESPath specification compliance.
